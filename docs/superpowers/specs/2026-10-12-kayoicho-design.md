# かよい帳 (kayoicho) 設計

GPSで自分が行った建物を自動で記録し、訪問の履歴と「何回行ったか」を残す iPhone/Android アプリ。

## 決めたこと

- **記録は自動**。アプリを閉じていてもバックグラウンドでGPSを受け取り、滞在を検出する（手動チェックインは無し）。
- **建物の名前は OpenStreetMap（Overpass API）から自動でつける**。APIキー不要。見つからなければ「名前のない場所」とし、ユーザーが名前を変えられる。
- **データは端末内だけ**（expo-sqlite）。クラウド同期・アカウントは無し。
- **画面は 履歴 / ランキング / 地図 の3タブ**。ランキングの建物をタップするとその建物の訪問日時一覧と名前変更。曜日・時間帯の分析は作らない。

## 技術

- Expo SDK 56（JavaScript）。既存の におい標・釣りスポナビ と同じ作り。
- expo-location（バックグラウンド位置更新）＋ expo-task-manager
- expo-sqlite
- 地図は Leaflet ＋ OpenStreetMap タイルを react-native-webview で表示
- テストは jest（`src/lib` の純粋関数）
- 画面確認は Expo Go ＋ iOS シミュレータ（位置をシミュレートして動かす）

## 滞在判定の定義

- **滞在** = 半径 50m 以内に 5 分以上とどまったこと。
- 精度（accuracy）が 100m より悪い点は捨てる（GPSの飛び対策）。
- 滞在の中心座標 = 含まれる点の平均。
- **同じ建物** = 既存の建物の中心から 40m 以内。該当が複数あれば最も近いもの。
- 同じ建物への滞在が 10 分以内の途切れで続いた場合は 1 回の訪問にまとめる（建物内でGPSが一瞬外れた対策）。
- 回数 = その建物への訪問（まとめた後）の件数。

これらの数値は `src/lib/config.js` に定数としてまとめる。

## 構成

```
src/lib/          純粋関数（テストあり、React/Expo に依存しない）
  config.js       判定の数値
  geo.js          2点間の距離（ハバーサイン）
  stay.js         座標の列 → 滞在の列（到着・出発・中心）
  match.js        滞在 → 既存の建物か新しい建物か、近い訪問をまとめる
  stats.js        建物ごとの回数・合計滞在時間・初回/最終訪問、ランキングの並べ替え
  naming.js       Overpass の応答（JSON）→ 最も近い名前付き候補を選ぶ
src/services/
  db.js           expo-sqlite。points / visits / places の3テーブル
  tracker.js      バックグラウンド位置タスク。受け取った座標を points に追記するだけ
  process.js      未処理の points を stay → match → DB 反映。アプリ起動時と位置タスクの中で呼ぶ
  overpass.js     Overpass API への問い合わせ（タイムアウト・失敗時は null）
app/ (expo-router)
  (tabs)/index.js     履歴
  (tabs)/ranking.js   ランキング
  (tabs)/map.js       地図
  place/[id].js       建物の訪問日時一覧＋名前変更
```

## データ

- `points(id, lat, lng, accuracy, timestamp, processed)`
- `places(id, name, name_source['osm'|'user'|'none'], lat, lng, created_at, naming_pending)`
- `visits(id, place_id, arrived_at, departed_at)`

回数・合計時間は visits から集計する（places に回数を持たない＝ずれない）。

## データの流れ

1. tracker が座標を受け取る → points に保存
2. process が未処理の points から滞在を切り出す。最後の滞在が「まだ続いている」可能性がある場合は確定させず次回に回す
3. 滞在を既存の建物と照合。新しい建物なら places に登録して名前を問い合わせ
4. visits に追加（直前の同じ建物の訪問と 10 分以内なら延長）
5. 処理済みの points は 30 日経ったら削除

## 画面

- **履歴**：日ごとの見出し＋「9:05〜9:40 ローソン渋谷店（35分）」。タップで建物の画面へ。
- **ランキング**：回数順（「合計時間順」に切り替え可）。各行に 回数・合計時間・最終訪問。タップで建物の画面へ。
- **地図**：建物をピン（円）で表示、回数が多いほど大きい。タップで名前と回数。
- **建物**：名前（変更可）、回数、初回/最終訪問、訪問日時の一覧。
- 位置情報が「常に許可」でないときは、全タブ上部に「記録が止まっています」と許可への導線を出す。

## エラー時の扱い

- 位置情報の許可：初回に理由を説明してから「使用中のみ」→「常に」の順で求める。拒否なら記録停止の帯を出す。
- 名前検索の失敗・タイムアウト：建物は登録し `naming_pending` を立て、次回の process で再試行。記録は失わない。
- ユーザーがつけた名前（name_source='user'）は自動で上書きしない。

## テスト

`src/lib` を jest でテストする。最低限のケース：
- 駅に 5 分いた → 滞在 1 件
- 通り過ぎただけ（4 分・移動中）→ 滞在 0 件
- 精度の悪い点が 1 つ飛んだ → 滞在は切れない
- 同じ建物に 2 日行った → 建物 1 件・訪問 2 件
- 建物内で 3 分 GPS が外れた → 訪問 1 件にまとまる
- 隣り合う 2 店（60m 離れ）→ 別の建物
- Overpass 応答から最も近い名前付き候補を選ぶ／候補なし → null
- ランキングの並び（回数順・合計時間順、同数は最終訪問が新しい順）

画面は iOS シミュレータで位置を動かし、滞在が履歴・ランキング・地図に出るところまで確認する。

## 正直に書いておく制約

- iOS は電池節約のためバックグラウンドの位置更新を間引くことがあり、数分だけ寄った場所は取りこぼすことがある。
- バックグラウンド位置は Expo Go では制限があるため、実機で常時記録するには development build が必要になる可能性がある（実装時に確認し、README に書く）。
- 民家・小さな建物は OpenStreetMap に名前が無いことが多い。
